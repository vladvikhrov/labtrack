# Глоссарий терминов LabTrack

| Термин | Определение |
|---|---|
| **LabTrack** | Веб-приложение для учёта состояния оборудования компьютерного класса с помощью QR-кодов. |
| **Устройство** | Единица оборудования класса, на которую наклеен QR-код: компьютер (ПК), принтер или проектор. |
| **Код устройства** | Короткий идентификатор устройства в системе, например `pc-15`. Входит в адрес страницы и в QR-код. |
| **Инвентарный номер** | Номер устройства по бухгалтерскому учёту учебного заведения, например `ИНВ-52-37-015`. Печатается на наклейке для сверки. |
| **QR-код** | Двумерный штрихкод, который камера телефона превращает в ссылку. В LabTrack ведёт на страницу конкретного устройства. |
| **Наклейка** | Этикетка 50×30 мм с QR-кодом, названием устройства и инвентарным номером. |
| **Страница устройства** | Экран, который открывает студент после сканирования: название устройства, его статус и кнопки «Всё работает» / «Есть проблема». |
| **Отметка** | Любое сообщение о состоянии устройства, отправленное через страницу устройства. |
| **Отметка «Всё работает»** | Подтверждение от студента, что устройство исправно. Показывает лаборанту дату последней проверки. |
| **Жалоба** | Отметка «Есть проблема» с одной или несколькими категориями неисправности. |
| **Категория неисправности** | Узел или тип проблемы: мышь, клавиатура, монитор, ПО, нет интернета и т. д. Для принтеров и проектора свой список. |
| **Открытая жалоба** | Жалоба, которую лаборант ещё не закрыл. Влияет на статус устройства. |
| **Закрыть жалобу** | Действие лаборанта «Отметить исправленным»: все открытые жалобы устройства становятся устранёнными, в историю добавляется запись об обслуживании. |
| **Обслуживание** | Запись лаборанта в истории устройства о выполненной работе, например «Заменена мышь». |
| **Статус устройства** | Вычисляемое состояние: «Исправно» (0 открытых жалоб), «Есть жалобы» (1–2), «Требует ремонта» (3 и более). |
| **Дашборд** | Главный экран лаборанта: сводные показатели, карта класса, список «Требуют внимания», жалобы по типу и журнал сообщений. |
| **Карта класса** | Схема расположения устройств в аудитории; цвет плитки показывает статус, число в кружке — количество открытых жалоб. |
| **История устройства** | Хронологический список всех отметок и записей обслуживания по одному устройству: когда, что и кто сообщил. |
| **Журнал сообщений** | Общая лента последних отметок по всем устройствам класса. |
| **Лаборант** | Пользователь с ролью «лаборант»: сотрудник, отвечающий за исправность оборудования. Работает с дашбордом, устройствами, наклейками и пользователями. |
| **Студент** | Пользователь с ролью «студент»: сканирует QR-код и отправляет отметки. Видит только страницы устройств и свои сообщения. |
| **Учётная запись** | Логин, пароль, ФИО и учебная группа пользователя в LabTrack. Нужна для отправки отметок и работы с дашбордом. |
| **Роль** | Уровень доступа пользователя: «студент» или «лаборант». Определяет, какие разделы доступны. |
| **Авторизация (вход)** | Проверка логина и пароля. После входа система помнит пользователя 30 дней. |
| **Код регистрации** | Общий код аудитории (например, CODE123), по которому студент может сам создать учётную запись. |
| **Временный пароль** | Пароль, который выдаёт лаборант при создании пользователя или сбросе пароля. Рекомендуется сменить после первого входа. |
| **Блокировка** | Запрет входа для учётной записи, устанавливается лаборантом. |
| **Демо-данные** | Тестовые пользователи и сообщения, которые создаёт команда `flask seed --demo` для показа системы. |
| **Списанное устройство** | Устройство, выведенное из эксплуатации: скрыто с карты класса, его QR-код не принимает отметки, история сохраняется. |
| **Прототип** | Работающая упрощённая версия системы для демонстрации основных функций. |
| **База данных (БД)** | Файл SQLite, в котором хранятся пользователи, устройства, отметки и настройки. Схема описана в `docs/01-db-schema.md`. |
| **Сервер** | Компьютер в интернете или сети колледжа, на котором работает LabTrack. Развёртывание описано в `docs/05-deploy.md`. |
| **Резервная копия** | Копия файла базы данных, по которой можно восстановить все данные. |
| **Пилот** | Пробный запуск системы на одной учебной группе перед запуском для всех. |
